# Роудмап впровадження системи підписок (Freemium)

## Етап 1: Архітектура БД (Базовий рівень)
- [x] Додати поля в таблицю `profiles`: `is_pro`, `subscription_id`, `subscription_status`, `pro_until`.
- [x] Визначити метод видачі прав адміністратору (ручне редагування БД).
- [ ] Оновити глобальний стан (React Context / Zustand) або хуки, щоб поле `is_pro` завантажувалось під час авторизації і було доступним на всіх сторінках.

## Етап 2: Інтерфейс пейволу (UI)
- [ ] Створити компонент `ProModal.tsx` (Спливаюче вікно з пропозицією підписки).
- [ ] Створити маркетингову сторінку `/pricing` з порівнянням тарифів (Free vs PRO).

## Етап 3: Обмеження функціоналу (Gatekeeping)
- [ ] Заблокувати запуск Офлайн-режиму (перехід на `Live Mode`).
- [ ] Обмежити створення сетлістів (перевірка кількості + виклик модалки).
- [ ] Заблокувати тумблер "Для команди" (Team Workspace).
- [ ] Заблокувати кнопку "Експорт PDF".
*Примітка: Усі заблоковані кнопки викликають `ProModal.tsx` із зазначенням функції, яку хотів використати юзер.*

## Етап 4: Інтеграція платіжного шлюзу (Lemon Squeezy / Paddle)
- [ ] Створити акаунт у платіжній системі, налаштувати продукт "PRO Підписка".
- [ ] Згенерувати посилання на чекаут (Checkout URL) та прив'язати його до кнопок на сторінці `/pricing`.
- [ ] Передавати `user_id` у метаданих платежу, щоб система знала, хто саме платить.

## Етап 5: Вебхуки та автоматизація (Backend)
- [ ] Створити API Route (напр. `/api/webhooks/payments`) у Next.js.
- [ ] Налаштувати обробку подій `subscription_created`, `subscription_renewed`, `subscription_cancelled`.
- [ ] Усередині API Route: автоматично оновлювати `is_pro` на `true` або `false` в Supabase при зміні статусу платежу.
